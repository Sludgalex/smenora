# Участие в проекте SMENORA

Публичный репозиторий `smenora` используется для пользовательской документации, release notes и обратной связи. Рабочий исходный код продукта хранится отдельно в закрытом репозитории.

## Перед созданием Issue

1. Укажите точную версию SMENORA.
2. Проверьте, воспроизводится ли проблема после перезапуска.
3. Если доступно, выполните встроенный self-test/диагностику.
4. Не прикладывайте рабочий `data.json`, реальные резервные копии или служебные выгрузки.
5. Удалите персональные данные, PIN, токены, пароли и ключи из текста, скриншотов и логов.

Для ошибок используйте шаблон Bug Report. Для новых функций — Feature Request.

## Документация

Pull Request в публичный репозиторий уместен для исправления опечаток, ссылок и пользовательской документации, если изменение не раскрывает внутренний исходный код или чувствительные технические сведения.

## Изменения исходного кода

Публичные PR с заменой внутренних исходников SMENORA не являются основным процессом разработки. Исходный код, тесты, build/release scripts и внутренняя архитектурная документация ведутся в закрытом репозитории.

## Архитектурный принцип

Редакции Start / Standard / Professional используют одну кодовую базу. Attendance и Compensation развиваются как подключаемые модули через стабильный Core API. Изменения архитектуры не должны создавать отдельные продуктовые ветки по редакциям.

## Безопасность

Уязвимости, которые нельзя безопасно описать публично, не публикуйте в GitHub Issues. Используйте закрытый канал связи через официальный сайт проекта: https://smenora.ru/.
